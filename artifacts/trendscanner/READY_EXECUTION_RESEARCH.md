# Проверка исполнения READY

`ready_execution_research.py` проверяет сценарии сделок по уже сохранённым
событиям READY и исходным OHLC-свечам. Это следующий этап после MFE/MAE:
положительная разница максимальных движений не означает, что сделка была
прибыльной. Стоп мог сработать до последующего движения к цели.

## Контракт модели

- Поддерживаются READY 1h/4h и линейные контракты. Timestamp события — время
  открытия сигнальной свечи; вход моделируется на открытии следующей свечи.
- Стоп и цель задаются процентами от исполненной цены входа. Значения,
  максимальный срок удержания и все издержки обязательны; автоматического
  подбора или торговых параметров по умолчанию нет.
- Вход и выход — модель рыночного исполнения с неблагоприятным фиксированным
  проскальзыванием. Это не модель лимитного take-profit.
- При гэпе через уровень выход происходит по цене открытия с проскальзыванием,
  поэтому убыток может превышать расстояние до стопа.
- Если внутри свечи задеты оба уровня и открытие не разрешает порядок,
  основной результат использует stop-first, дополнительный — target-first.
  Такие события явно отмечаются; точный путь цены по OHLC восстановить нельзя.
- Если уровни не достигнуты, выход — close последней свечи горизонта.
- Используются только полностью закрытые к `as_of_ms` свечи. Неполный
  горизонт даёт `CENSORED`, отсутствие или неоднозначность необходимых свечей
  — `INVALID`. Известный ранний выход не требует свечей после выхода.
- Комиссии считаются на фактических входном и выходном номиналах.
  `funding_cost_bps` — явно заданный совокупный сценарный расход от входного
  номинала, а не восстановленный исторический funding. Нулевое значение
  означает явное исключение этого расхода.

`net_return_pct` — результат на входной номинал после заданных издержек.
Это не доходность депозита и не результат с плечом. Кандидаты оцениваются
независимо: одновременные позиции, ограничения капитала, маржа, ликвидация и
портфельная просадка здесь не моделируются.

CURRENT и HOLDOUT получают отдельные показатели LONG/SHORT. Их доходность
не объединяется. Пересечение периодов проверяется с учётом всего возможного
горизонта исходов HOLDOUT; дубли событий вызывают ошибку. Вместе с результатами
сохраняются параметры, число обработанных/неполных событий и неоднозначных свечей.

## Входные файлы и запуск

Используются существующие `ready_outcome_results.json` и
`ready_outcome_holdout_results.json` с `runs[].events`. Одних MFE/MAE недостаточно:
для исполнения нужны исходные свечи с колонками `time,open,high,low,close`.
`time` — Unix milliseconds. Имена и периоды файлов задаются явно в manifest;
относительные пути считаются от его папки.

Пример структуры manifest (это описание входных файлов, не реальные данные):

```json
[
  {"period":"CURRENT","symbol":"BTC/USDT","timeframe":"4h","path":"current_btc_4h.csv"},
  {"period":"HOLDOUT","symbol":"BTC/USDT","timeframe":"4h","path":"holdout_btc_4h.csv"}
]
```

Файл сценария содержит все поля `stop_pct`, `target_pct`, `max_bars`,
`entry_fee_bps`, `exit_fee_bps`, `slippage_bps`, `funding_cost_bps`.
Один базисный пункт — 0.01%. Комиссии и сценарные значения требуется задать
отдельно; значения синтетических тестов не являются предложенной стратегией.

```bash
python artifacts/trendscanner/ready_execution_research.py \
  --current artifacts/trendscanner/ready_outcome_results.json \
  --holdout artifacts/trendscanner/ready_outcome_holdout_results.json \
  --manifest research_inputs/manifest.json \
  --scenario research_inputs/scenario.json \
  --as-of-ms YOUR_FIXED_CUTOFF_MS \
  --output research_outputs/ready_execution_report.json
```

Код выхода 0 означает полное покрытие переданных событий. Код 2 означает
пустую или неполную выборку; отчёт при этом сохраняется. Недопустимые входные
данные вызывают ошибку. Скрипт не запрашивает биржу и не повторяет signal replay.

## Как применять к разработке стратегии

Сначала зафиксировать сценарий входа/выхода и издержек до чтения результатов.
Затем проверить одинаковый сценарий отдельно на CURRENT и HOLDOUT, включая
долю пропущенных событий и чувствительность к порядку касаний. При наличии
нескольких исследуемых сценариев нужно учитывать факт множественных проверок;
исследованный HOLDOUT уже нельзя считать новым независимым подтверждением.

Этот PR проверяет корректность вычислений на синтетических данных.
Исходные архивы свечей и событий CURRENT/HOLDOUT в репозитории отсутствуют;
эмпирическая доходность стратегии этим изменением не установлена. Следующий
обоснованный шаг — прогон на этих сохранённых входных файлах, затем выбор
правил, устойчивых к издержкам и периоду наблюдения.

## Проверка

```bash
python -m pytest -q artifacts/trendscanner/test_ready_execution_research.py
```

Тесты покрывают LONG/SHORT, вход после сигнала, выходы, гэпы, неоднозначные
свечи, издержки, неполные окна, отсутствие влияния цен после выхода,
границу CURRENT/HOLDOUT и запуск CLI на сохранённых файлах.
