────────────────────────────────────
ЧАСТЬ 1. SETTINGS.PY
────────────────────────────────────

1. Создай новый файл:

settings.py

2. Перенеси туда только настройки Product/UI Layer:

TOP_SETUPS_LIMIT = 10

TOP_SETUPS_MIN_DECISION_SCORE = 25.0

SHOW_WATCH_IN_TOP_SETUPS = True

SHOW_SKIP_IN_TOP_SETUPS = False

SHOW_WAIT_SIGNALS_BY_DEFAULT = False

SHOW_ALL_SYMBOLS_BY_DEFAULT = False

DEFAULT_RESULT_PAGE_SIZE = 10

MAX_RESULT_PAGE_SIZE = 50

CACHE_TTL_SECONDS = 60

3. Пока не переноси в settings.py внутренние веса аналитических движков.

Confidence weights и торговые пороги остаются в своих текущих модулях.

4. Добавь комментарии:

- эти значения управляют отображением и ранжированием;
- они не меняют торговую логику;
- TAKE/WATCH/SKIP по-прежнему определяет decision_engine.py.

────────────────────────────────────
ЧАСТЬ 2. TOP SETUPS ENGINE
────────────────────────────────────

5. Создай независимый файл:

top_setups.py

Он не должен импортировать Streamlit.

6. Создай функцию:

build_top_setups(
    symbol_results: dict,
    limit: int = TOP_SETUPS_LIMIT,
    min_decision_score: float = TOP_SETUPS_MIN_DECISION_SCORE,
    include_watch: bool = SHOW_WATCH_IN_TOP_SETUPS,
    include_skip: bool = SHOW_SKIP_IN_TOP_SETUPS,
) -> list[dict]

7. Входной формат:

symbol_results = {
    "BTC/USDT": multi_analysis_result,
    "ETH/USDT": multi_analysis_result,
    ...
}

8. Для каждого символа безопасно извлекай из result["FINAL"]:

- signal;
- confidence;
- confidence_label;
- directional_score;
- decision;
- decision_direction;
- decision_score;
- decision_directional_score;
- decision_reason;
- decision_counts;
- available_timeframes.

9. В Top Setups допускаются:

TAKE — всегда, если данные валидны.

WATCH — только если include_watch=True
и decision_score >= min_decision_score.

SKIP — только если include_skip=True.

10. По умолчанию не включай:

- ERROR;
- полностью отсутствующие данные;
- SKIP;
- WATCH с decision_score ниже порога;
- записи с decision_direction == NONE,
  кроме случая, когда явно включён include_skip.

11. Верни каждую запись в формате:

{
    "rank": int,
    "symbol": str,
    "decision": "TAKE" | "WATCH" | "SKIP",
    "direction": "LONG" | "SHORT" | "NONE",
    "decision_score": float,
    "confidence": float,
    "confidence_label": str,
    "signal": "LONG" | "SHORT" | "WAIT",
    "directional_score": float,
    "decision_reason": str,
    "available_timeframes": int,
    "take_count": int,
    "watch_count": int,
    "raw_result": dict
}

12. raw_result нужен для перехода к подробному отображению,
но не должен напрямую выводиться пользователю.

13. Сортировка:

Основной приоритет:

TAKE выше WATCH выше SKIP.

Внутри одной категории:

1. decision_score по убыванию;
2. confidence по убыванию;
3. available_timeframes по убыванию;
4. symbol по алфавиту для стабильности.

14. После сортировки присвой rank начиная с 1.

15. Ограничь результат limit.

Некорректные limit:
- меньше 1 → использовать 1;
- больше MAX_RESULT_PAGE_SIZE → ограничить MAX_RESULT_PAGE_SIZE.

16. Не изменяй переданные symbol_results.

21. summarize_decision_factors возвращает:

Что вижу
Сам сканер ещё работает:

есть строка Scanning ADA/USDT...;

прогресс-бар не завершён;

значит цикл анализа ещё не закончился.

При этом отображается:

Updated: 15:41:50
а на телефоне уже

18:42
То есть время обновления явно не соответствует текущему.

Скорее всего причина одна из двух
Вариант 1 (самый вероятный) — время берётся в момент первого рендера
Например, сейчас где-то есть что-то вроде:

updated = datetime.now().strftime("%H:%M:%S")
st.write(updated)
или

UPDATED = datetime.now()
Если страница не перерисовывается полностью, это время больше не меняется.

Вариант 2 — используется серверное время Replit
Иногда Replit показывает время контейнера (обычно UTC), а телефон — локальное.

Но здесь разница почти 3 часа, что очень похоже именно на часовой пояс.

Я бы сейчас сделал лучше

Updated: 15:41:50

🟢 Last successful scan

Last completed:
18:42:31
